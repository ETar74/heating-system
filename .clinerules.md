# КРИТИЧЕСКИЕ ПРАВИЛА БЕЗОПАСНОСТИ (НИКОГДА НЕ НАРУШАТЬ)
1. При старте ВСЕ реле принудительно LOW ДО чтения NVS.
2. NVS читается только при совпадении magic number (0xDEADBEEF); иначе safe defaults.
3. Перед ЛЮБЫМ решением о нагреве: проверка sensors.isSensorValid(role).
   Невалидный датчик => контур ВЫКЛ. Никогда не использовать 0.0 / -127.0 / 85.0 в логике.
4. Критические пороги (CRITICAL_BOILER_TEMP_MAX и т.п.) хардкодом, НЕ изменяемы через веб/NVS.
5. Иерархия приоритетов: emergency stop > критические пороги > sensor fault > manual > расписание > удалённые команды.
6. Запись в NVS ТОЛЬКО при изменении данных (ресурс flash ~100k циклов).
7. Никаких блокирующих вызовов в TaskControl. HTTP-запросы только с setTimeout().

# КАТАЛОГ ИЗВЕСТНЫХ ГРАБЛЕЙ (НЕ ВОЗВРАЩАТЬ ЭТИ БАГИ)
1. FreeRTOS стек: TaskNextion требует >= 8192 байт. Контроль: uxTaskGetStackHighWaterMark().
   Никаких цепочек String (substring/replace/+=) в горячих путях задач — только char[] + snprintf/sscanf.
2. Nextion UART: ИСХОДЯЩИЕ команды завершаются 0xFF 0xFF 0xFF. ВХОДЯЩИЕ команды приходят
   СКЛЕЕННЫМИ ("pg2pg0", "sch_dev_2pg2") — парсить через rxBuffer + extractCommand() со списком известных команд.
3. hasCommand() обязан проверять И Serial2.available(), И rxBuffer.length().
4. В цикле while(hasCommand()): при пустой команде — break, НИКОГДА continue (иначе infinite loop).
5. UTF-8/кириллица через UART вешает Nextion. Динамические тексты — ТОЛЬКО ASCII.
   Кириллица допустима только статикой в Nextion Editor.
6. DeviceEvent хранит char type[16] / char message[64], НЕ const char* (dangling pointer).
7. Веб присылает deviceId 1..4; массивы ESP32 — 0..3. ВСЕГДА нормализовать (devId--).
8. После применения SET_SCHEDULE из сети: storage.saveSettings() + nextion.resetCache(),
   если currentPage == 7 и scheduleDevice == совпал (иначе экран не обновится).
9. delay() запрещён в TaskControl; в TaskNextion допустим только короткий (<=300 мс) при смене страницы.
10. В классе Nextion публичны: currentPage, scheduleDevice, resetCache(). Не делать их private.
11. #define конфигурации живут ТОЛЬКО в config.h. Дубли в network.h/других заголовках запрещены.
12. Объявления методов в .h и реализации в .cpp обязаны совпадать сигнатурами
    (handleKeypadInput принимает const String&).
